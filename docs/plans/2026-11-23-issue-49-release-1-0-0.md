# Plan: Prepare release 1.0.0 (issue #49)

Risk tier: Low. The engine code is the same as 1.0.0rc2, which the owner tested against the OPEN backend; only the version string changes. The rest is wording, the changelog, and test pins the version moves. Recorded without a human gate: the owner delegated plan approval for this run.

Domain skills: none apply. No Django, API framework, UI, auth, payments, or email code is touched.

This PR does not tag, publish, or create a GitHub release. The owner does those. Issue #49 stays open until the owner publishes.

## Acceptance criteria

1. `src/open_engine/_version.py` sets `__version__ = "1.0.0"`. No other line under `src/` changes. No parameter value, no `parameter_fingerprint()`, and nothing in `tests/api_surface.txt` changes.
2. `CHANGELOG.md` has one `## [1.0.0] - 2026-11-23` section in place of the `1.0.0rc1` and `1.0.0rc2` sections, covering everything since 0.3.0.dev0 in the existing format (intro, highlights, Added, Changed, Fixed, Security). It says 1.0.0 is the same code as 1.0.0rc2, keeps the reference-implementation statement and "outputs are not OPEN ratings", records the new default `Config().fingerprint()`, and says `parameter_fingerprint()` does not change. The compare links are updated.
3. Wording that says the stability promise takes effect at, or applies from, 1.0.0, or that the API may change in any 0.x release, now says the promise is in effect: README "Public API", `docs/behavior.md` "Stability", `CLAUDE.md`, and the changelog preamble. The status note, Known limitations, "Its outputs are not OPEN ratings", and "Do not use it to rate real players" stay (issue #161 keeps them; #49 has no comments that change this).
4. Every install instruction for users is `pip install openpickleball-engine` from PyPI, with no TestPyPI index, `--pre`, or exact pin needed. `docs/releasing.md` keeps its TestPyPI rehearsal check, with the example version updated.
5. The version bump moves `Config.fingerprint()` and three snapshot hashes; the pins are updated, and for each snapshot hash the 1.0.0 snapshot text with the version and fingerprint strings swapped back hashes to the 1.0.0rc2 pin.
6. The gate passes: `ruff check .`, `ruff format --check .`, `mypy src`, `pytest -n auto`; a local build passes `check_sdist.py`, `check_wheel.py`, `check_installed_wheel.py`, `check_release.py v1.0.0`, and `twine check --strict`.

## Files that change

- `src/open_engine/_version.py`: the version.
- `CHANGELOG.md`: the merged 1.0.0 section, the preamble, the links.
- `README.md`: Install section, "Public API" opening sentences.
- `docs/behavior.md`: "Stability" opening paragraph.
- `docs/releasing.md`: the install check example version, and the step 1 line about the README install line.
- `CLAUDE.md`: the setup note ("not on PyPI yet") and the Public API rule.
- `tests/test_readme.py`: checks the README install line is the plain PyPI install, instead of a TestPyPI pin.
- `tests/test_api.py`: checks the README API section states the Semantic Versioning promise, instead of the 0.x sentence.
- Fingerprint and snapshot hash pins in ten test files, as in the 1.0.0rc2 PR.

- `pyproject.toml` keeps the `Development Status :: 2 - Pre-Alpha` classifier and "not for production use" in the description. Changing the classifier is a judgment for the owner, so this PR leaves it.
