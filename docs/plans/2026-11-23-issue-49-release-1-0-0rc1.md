# Plan: Prepare release 1.0.0rc1 (issue #49, preparation only)

Risk tier: Medium. No rating math changes, but the version bump changes every `Config.fingerprint()` and every snapshot that carries the config version, and the status wording changes in about twenty files. Plan approval was delegated by the maintainer for this run.

Domain skills: django, django-ninja, celery, allauth, FastAPI, React, Expo: not applicable because this is a pure Python package with no web or app layer. humanizer: not invoked; the repo's own writing style rules apply.

This pull request prepares the release. It does not tag, publish, or create a GitHub release, and it does not change the release workflow or any repository setting. The maintainer tags and publishes. The pull request says "Part of #49" and does not close it.

## Acceptance criteria

1. `src/open_engine/_version.py` sets `__version__ = "1.0.0rc1"`. `scripts/check_release.py` accepts tag `v1.0.0rc1` with `openpickleball_engine-1.0.0rc1.tar.gz` and `openpickleball_engine-1.0.0rc1-py3-none-any.whl`, and a built sdist and wheel carry that version.
2. The README TestPyPI install line pins `1.0.0rc1` (`tests/test_readme.py` checks it).
3. `CHANGELOG.md` moves the `[Unreleased]` entries under `## [1.0.0rc1] - 2026-11-23`, with a short summary at the top of the section: parameter set identity (#155), API freeze and the stability promise (#156), parameter set v1 (#48), the declared meaning of a rating gap (#149), and the breaking changes (snapshot version 9, the new `PlayerSummary` fields, the `self_reported_log` rename). It says the stability promise in `docs/behavior.md` takes effect at 1.0.0, not at a release candidate. It keeps the reference-implementation statement and "outputs are not OPEN ratings". It records the new `Config()` fingerprint, `4012bfec9bfddd48`, and that `parameter_fingerprint()` does not change. An empty `[Unreleased]` section and the compare links are updated.
4. The status wording, in the README, `docs/model.md`, `docs/behavior.md` "Status", the docstrings of `__init__.py`, `engine.py`, and every private module that carries the label, the `pyproject.toml` description, `docs/parameters.md`, `PARAMETERS.md`, and `CLAUDE.md` ("Current status" and hard rule 3):
   - no longer says the API may change without notice;
   - no longer says "not validated on real match data"; it says the engine was evaluated on one club's closed pool (1,601 doubles matches, 189 players), that a forthcoming report describes the evaluation, and that the default-change rule did not pass its gain bar, so the `Config()` defaults remain placeholders and v1 is loaded explicitly; it does not link the private evaluation repository;
   - keeps "not OPEN ratings" and "no OPEN rating is live";
   - says ratings are provisional: they come from one club's closed pool, pools that share no players are not comparable, and parameters are retuned on a published schedule (issue #48, `docs/parameters.md`).
   The label "demonstration" becomes "reference implementation". The README keeps "The API may change in any 0.x release." until 1.0.0 final.
5. `tests/test_docstrings.py` requires the new label in the `engine.py` docstring, and a test fails if any module docstring in `src/open_engine/` says the API may change without notice or omits "not OPEN ratings".
6. `docs/releasing.md` is changed only where it is now wrong: the demonstration label, and the version-form and failed-upload rules, which did not cover a release candidate (`1.0.0rc1`, then `1.0.0rc2`).
7. A public issue on openpickleball/engine records the wording decision, links #156 and #49, and the pull request links it.
8. The gate passes: `ruff check .`, `ruff format --check .`, `mypy src`, `pytest -n auto`.

## Order of work

1. Bump the version and repin the fingerprints the bump changes. Confirm only config-version hashes moved.
2. Change the docstring test first, see it fail, then change the docstrings.
3. Change the docs, `pyproject.toml`, and `CLAUDE.md`.

## Risks

- Repinning a fingerprint could hide a real change. Only pins whose old value came from `Config.version` move; every rating, evaluation, and fit pin must stay the same.
- The README install line names a version that is not on TestPyPI until the maintainer tags it, as with earlier releases.
- `tests/api_surface.txt` records `Config` defaults; it must not change, since `version` is read from `_version.py`.
