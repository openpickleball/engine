## Risks

- Repinning could hide a real change. Only `fingerprint()` values and the replay snapshot hash (which carries the config version) move; every rating and `parameter_fingerprint()` pin stays.
- The PyPI job runs only after TestPyPI succeeds, so a TestPyPI failure blocks PyPI. That is intended: TestPyPI is the rehearsal.
- If the pypi.org pending publisher is not registered before the tag, `publish-pypi` fails after TestPyPI has taken the version; the fix is the next rc number. `docs/releasing.md` says to register it first.
- The README install line names a version that is not on TestPyPI until the maintainer tags it, as with earlier releases.
- Not done: no switch of the README install line to PyPI (that waits until rc2 is actually on PyPI), no change to `CLAUDE.md`'s "not on PyPI yet" setup note for the same reason.
